# pi-web-simple：给 pi 加一个本地 Web UI

pi 的终端界面我一直用着挺舒服，但有几件事在终端里做起来别扭：

- 它一边改文件，我想一边点开某个文件看看改成什么样了，而不是等它跑完再 `git diff`
- 同时开着五六个会话，想一眼看出哪个在跑、哪个在等我
- 想看看这一轮动了哪几个文件，而不是在 scrollback 里往上翻

所以就动手写了这个：**pi-web-simple**，一个本地 Web UI，pi 还是那个 pi，只是在外面套了一层壳。

![主界面](https://cdn.jsdelivr.net/gh/woxihejinghao/pi-web@main/docs/images/overview-dark.png)

## 它是什么

一句话：**一个本地目录 = 一个项目**，项目下挂这个目录的会话，agent 内核是 pi 本身，通过 `pi --mode rpc` 子进程接进来。

几个设计上的选择，我觉得挺关键：

- **会话列表不是另存一份。** 页面里的列表是实时从 pi 自己的存储里读出来的，你在终端 `pi --resume` 看到的会话和页面里的是同一批，不会出现「两边各有一份记录」的情况。
- **每个会话一个 pi 进程，懒启动 + 空闲回收。** 不打开的会话不占资源，打开过的放在那儿待命。
- **界面是照着 deepseek-harness 做的。** 左栏工作区，中间对话，右栏文件 / 变更 / 终端 / 浏览器，用惯 dsh 的话基本不用重新学。

## 改了名字，终端里也是新名字

会话重命名是追加进 pi 会话文件里的 `session_info`，不是在 Web 这边另存一个覆盖项。

这件事看起来小，但它决定了「这个会话叫什么」只有一个答案。我在页面里把某个会话改叫「修登录超时」，回到终端 `pi --resume`，它就叫这个名字。反过来也一样。

## 右栏是能干活的地方

文件树、预览、Git 变更、终端、内嵌浏览器都在右栏，而且能分成左右两格，标签也能拖出来变成浮窗。

预览不只是文本：Markdown 会渲染，代码走 shiki 高亮，图片、PDF 直接看，HTML 是 `sandbox=""` 加一条 CSP 的静态预览，脚本一律不跑。

Git 那一格是完整的：看每个文件的 diff、暂存、提交、推送、切分支，不用切回终端。每一轮对话的末尾还会有一张「本轮改动」卡片，点开是这一轮改动的完整面板，左边选文件、右边看带行号的 diff。

![右栏的终端](https://cdn.jsdelivr.net/gh/woxihejinghao/pi-web@main/docs/images/promo/terminal.png)

终端是真的 PTY（xterm.js + node-pty）。有个细节我特意做成了这样：**关掉标签页才会杀掉那个 shell**，折叠右栏、切会话、刷新页面都只是断开，重新打开还在原来的地方接着看。后台跑着的构建不会被收起侧栏掐断。

右栏常用的几个动作有全局快捷键，绑定是直接从 dsh 抄的（`⌥⌘B` 收起右栏、`⌘P` 打开文件、`` ⌃` `` 新开终端……），两个应用之间的肌肉记忆能通用。

## 侧栏可以按自己的想法排

分组方式和排序方式都能选：分组有「按工作区 / 按工作区树 / 单列表」，排序有「手动排序 / 最近更新」。

选手动排序之后，工作区行和会话行都能直接拖着换位，插入线画在落点的那条边上。工作区的顺序存服务端（换台机器打开还是这个顺序），会话的手动顺序存在当前浏览器里。

![视图选项](https://cdn.jsdelivr.net/gh/woxihejinghao/pi-web@main/docs/images/promo/sidebar.png)

搜索框也从独立一行改成了在「工作区」分组头里就地展开，点一下就出来，Escape 收起。

## 设置页写的是 pi 自己的文件

模型、插件、MCP 三节改的都是 pi 自己读的那几个文件（`models.json` / `auth.json` / `mcp.json`），不是这里的私有配置，所以页面里配好之后终端里的 pi 直接就能用。

MCP 那节现在是直接按 pi 的合并规则读写两份 `mcp.json`（全局一份、工作区一份）。以前这里依赖 `pi-mcp-adapter`，pi 内置 MCP 支持之后就去掉了——留着那个扩展反而会替换掉内置的这套，页面上的「补一个依赖」实际变成了「换一个配置来源」。

## 怎么跑

```sh
npx pi-web-simple
```

默认在 `127.0.0.1:5319` 提供前端和 API，并自动打开浏览器。另外几种：

- `npm install -g pi-web-simple`，然后任意目录敲 `pi-web-simple`
- 已经泡在 pi 里的话：`pi install npm:pi-web-simple`，之后用 `/web` 起（`/web status` 看状态、`/web stop` 关掉，pi 退出时子进程也跟着结束，不会留下占着端口的孤儿进程）
- 桌面版在 [Releases](https://github.com/woxihejinghao/pi-web/releases) 里，mac / Windows / Linux 都有。它**自带 Node.js 运行时**，不用先装什么

桌面版和 CLI 共用 `~/.pi-web-simple` 与 `~/.pi`，看到的是同一批项目与会话，可以同时开着。

## 已知的坑

先把不好听的说完：

- **只监听 `127.0.0.1`，没有登录也没有鉴权。** 它是给自己电脑用的，别往外网放。
- **终端标签依赖可选的 `node-pty`**（原生模块）。平台没有预编译二进制时（比如 Linux）要本机编译；装不上只有那一个标签置灰，其余功能不受影响。
- **失败的那一轮只能「把这条 prompt 再发一次」，没有真正的重试。** pi 的重试循环只在 turn 内部跑，RPC 里没有对应入口。
- **变更面板没有左右对比视图**，HTML 预览也永远不跑脚本（这是刻意的，不打算加开关）。
- **桌面版还没有代码签名**：macOS 第一次打开要右键 → 打开，Windows 会弹一次 SmartScreen。
